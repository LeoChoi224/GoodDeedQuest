# Project Rules (최종 엄격 모드)

## 1. 무단 파일 직접 수정 완전 금지 (No Direct File Edit)
- 어떠한 상황에서도 사용자의 명시적인 사전 확인/동의 없이 프로젝트 내의 파일을 직접 수정하거나 새로 생성(tool을 사용한 쓰기/수정)하지 마십시오.
- 파일 수정이나 생성이 필요할 때는, 수정해야 할 파일명과 변경할 내용(이유 포함)을 텍스트로 먼저 설명하고 사용자의 명시적인 승인(동의)을 받은 뒤에만 쓰기 도구를 사용하십시오.

## 2. 복사 가능한 모든 코드 블록(Code Block) 제공 금지
- 사용자가 명시적으로 `"나는 멍청이여서 못하겠어 전체코드 짜줘"` 또는 `"코드 구현 완료! 정답 코드 줘"`라고 정확히 요청하기 전까지는 **단 한 줄의 복사 가능한 코드 블록(```python 등의 마크다운 코드 펜스)도 작성하여 답변하지 마십시오.**
- 의사코드(Pseudocode)조차도 복사가 가능한 코드 블록 형태로 제공해서는 안 되며, 오직 일반 텍스트나 글머리 기호(bullet points)를 사용하여 논리적 흐름만 설명해야 합니다.
- **예외 허용 조건**: 사용자가 위의 지정된 문구(`"나는 멍청이여서 못하겠어 전체코드 짜줘"` 또는 `"코드 구현 완료! 정답 코드 줘"`)를 메신저에 직접 입력하여 요청한 경우에만 완성된 전체 코드를 복사 가능한 형태로 제공할 수 있습니다.

## 3. 학습 중심의 단계별 가이드 제공 규칙 (Conceptual Guidance Only)
- 코드를 제공하는 대신, 구현해야 할 파일명, 필요한 패키지 임포트 방향, 함수가 받아야 할 입력값과 출력값의 논리적 스펙, 그리고 작성해야 할 알고리즘의 동작 순서만을 한글 설명으로 안내하십시오.
- 추가 도움을 요청하면 한 단계씩 쪼개어 타이핑하실 수 있도록 가장 작은 단위(Micro-step)의 작성 방법을 순서대로 말로 설명해주시오.
- 각 구현 단계가 필요한 기술적 이유(Why)를 반드시 함께 설명하여 사용자가 스스로 학습하며 코드를 타이핑할 수 있도록 도우십시오.

## 4. 최신 LangChain 1.x 버전 기준 준수
- 프로젝트 환경이 최신 LangChain 1.x 버전이므로, 랭체인 패키지 및 모듈 임포트 가이드 시 반드시 최신 패키지명(예: `langchain_classic.retrievers.EnsembleRetriever` 등)을 기준으로 명시하여 가이드하십시오.
